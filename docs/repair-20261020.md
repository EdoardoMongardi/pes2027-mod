  fields. Do not match Cristiano Ronaldo using a Ronaldo substring.

  executable patch and native number/name visibility patches are preserved.

## Data findings and repairs

The two identically named IPAs in D:/Telegram and D:/PES2027 contain different
dylibs, dt870 data and supplemental indices. Both contain ZiruOffline already;
neither is a pristine unmodified iOS reference.

The Legends CPK contains all 44,028 baseline player IDs plus 2,584 more, including
37576 and 9901397. However, replacing the whole baseline CPK loses 50 baseline-only
files, mainly kit configuration plus stadium/demo data. tools/merge_cpk.py creates
a 151-file union with the Legends payload taking precedence on identical paths,
retains baseline file IDs and assigns noncolliding IDs to additions. Every file
is read back and checked. The merged CPK has 46,612 player records.

The supplemental pc7999 also mixed directory roots. Its normalized index uses
../../../PesMobile/Content/Assets/, retains the union of 812 directory entries,
and keeps the cooked asset bytes. The ORI_IDS27 source has an extended 32-byte
package-store layout for independent textures. The previous tool interpreted
export-bundle byte size as export count by using a 16-byte stride. For 169
packages, the source is now recognized explicitly and translated to the native
16-byte store format. Every package is matched to byte-identical source payload
before its store entry is taken. All 536 cooked asset chunks remain byte-identical;
only the container-header chunk is rebuilt. All 21 package imports resolve in the
archived native package indices or the supplemental container.

179 directory aliases still have a package ID different from the ID generated
from their requested path, including the fabricated large/Variation2022 legend
aliases. They are retained for comparison, but are not counted as new working
assets. Correctly creating another texture package requires its own package ID
and export name. This candidate does not invent those assets or claim that listing
an alias proves rendering. Native shader/material/mesh compatibility and the exact
thumbnail paths requested by the client still require device checks.

## Build and verification

The runtime dylib was built and tested at 747598a in GitHub Actions run
39402782302. Both Linux and macOS jobs passed, including the offline gameplay,
mod ZIP recovery, table conversion, legend identity and resource-preservation
tests. The CPK and extended-store Python regression tests also pass locally.

The repair builder checks the input executable hash and CI dylib checksum,
preserves the executable, checks all ZIP CRCs, rejects duplicate paths, and checks
that unrelated bundle files remain byte-identical. It writes a new IPA and a JSON
report; it never overwrites either input IPA. Signing metadata is removed because
the resulting IPA must be signed again for installation.
